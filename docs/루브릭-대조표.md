# 루브릭 대조표 — 앱(v1.3) × 스킬(1.2-skill)

2026-08-28 작성. 코어 통합 회의용 자료 — 두 루브릭이 v1.2에서 갈라진 뒤의 전수 대조.
목표: **교육과정(정본)은 하나, 시험지는 둘** — 코어 정본 + 트랙별 확장으로 재편.
결과 표현은 점수 폐지·카테고리별 상태로 전환하기로 함(기획서 6장·design plan 결정 표 참조).

## 1. 실질 충돌 — 회의에서 결정할 것

| # | 충돌 | 내용 | 권고 |
|---|---|---|---|
| 1 | AI 표시·오류 고지 | S-ai-transparency·S-ai-fallibility가 **앱에만** 있음 → 스킬 통과 후 심사 탈락 위험. AI 기본법 근거 있음 | 코어 승격 — 스킬에 추가 |
| 2 | 저장 위치 기준 강도 | 앱 S-overseas "해외 저장 안내"만 vs 스킬 S-data-region "학교 도입이면 국내 저장" | 코어에서 조건부 통일: 개인 파일럿=안내 / 학교 정식 도입=국내 저장 |
| 3 | 중요도 체계 | 앱 필수/점수 vs 스킬 상/중/하. 예: S-sensitive가 스킬 '상' vs 앱 점수 3 | 매핑 규칙 합의 (스킬 '상' ↔ 앱 '필수' 후보 정렬, S-sensitive 필수 승격 검토) |
| 4 | 고지 항목 중복 | 앱 S-notice+S-consent ↔ 스킬 S-privacy-notice(법정 11종) — 스킬이 법적으로 정확 | S-privacy-notice로 통합 흡수 |

관련 열린 논점: 점수 폐지에 따라 EAS 발급 임계(80점) 재정의 필요 — 예: "필수 전항 충족 + Critical 0".

## 6. 항목이 아닌 상호 보완 장치

1. 스킬의 하위 점검 133개 → 앱 evidenceHint 구체화 소재
2. 스킬의 negative_scan(부재 증명 7항목) → 앱의 "없음" pass 근거 방식으로 역수입
3. 앱의 authority(법적 무게 4등급) ↔ 스킬의 basis(조항 단위) — 코어에 둘 다
4. 스킬의 출처 4종(scanner/code/evidence/teacher) ↔ 앱 오버라이드 체계 — 판정 어휘 통일
5. 카테고리 분류: 스킬의 8분류를 코어 공통 분류로 채택 (앱 결과 표현도 이 분류 기준)
